# 숏폼 영상 자동화 프로그램

주제를 넣으면 AI가 조사와 대본을 쓰고, **사람이 출처·대본·이미지·완성 영상을 확인·승인하면** 9:16 숏폼 영상 1편(mp4)이 나오는 프로그램이다.
4명 스터디 팀 프로젝트이며 **돈을 한 푼도 쓰지 않고**(무료 프로그램·무료 API만) 만든다.

- 기획: [`docs/영상자동화_4주_간소화_기획서_통합본_20261017.html`](docs/영상자동화_4주_간소화_기획서_통합본_20261017.html)
- 작업 규칙·코딩 규칙: [`CLAUDE.md`](CLAUDE.md)
- 공용 파일 형식과 기획서와 달라진 점: [`docs/공용파일_형식_변경.md`](docs/공용파일_형식_변경.md)
- 작업 기록(걸린 시간·막힌 곳·무료 한도, 시간순): [`docs/notes.md`](docs/notes.md)

## 0. 현재 상태 (2026-10-20 기준)

**한 줄기가 끝까지 돌아간다**: 주제 입력 → 조사·대본 → 승인 → 음성·이미지 → 이미지 확인 → 영상화·합성 → 승인 → 다운로드. 8GB PC에서 60초(9장면) 영상이 승인 대기를 빼고 약 3.6분에 나온다(실측은 6장).

| 구분 | 내용 |
|---|---|
| **구현 완료** | ①~⑦ 모든 단계, 승인 3개(승인 ①, 이미지 확인, 승인 ②)와 반려 시 되돌아가기, 장면 단위 다시 만들기(그림·스톡·대본), 이어서 실행, Streamlit 화면, 무료 한도 사용량 표시, 대체 수단(스톡→AI 그림→글자 카드) |
| **확인한 것** | 모든 단계를 실제 무료 서비스로 호출해 확인, **60초 9장면 영상 1편 완주**, 화면 헤드리스 시험 81항목 등 시험 묶음 14개 259항목(개발 중 임시 스크립트), 새로 복제해 설치·실행해 본 검증 |
| **아직 못 한 것** | 음성·움직임·합성의 장면 단위 다시 만들기, YouTube 인기 영상 참고(선택), 저장소에 올라간 자동 시험 파일, 분야가 다른 시험 주제 3개로 만든 시연용 영상과 팀원 교차 점검표 |
| **팀 결정이 필요한 것** | GitHub Private 저장소 생성(아직 로컬에만 있음), Pretendard 글꼴 라이선스 확인 후 저장소에 올릴지, 쓰이지 않는 `moviepy` 제거 여부, 공용 파일 형식 확정([변경 목록](docs/공용파일_형식_변경.md)) |

> 이 문서는 **사용법과 현재 상태**를 다룬다. 만든 과정과 막힌 곳(시간순)은 [`docs/notes.md`](docs/notes.md), 파일 형식은 [`docs/공용파일_형식_변경.md`](docs/공용파일_형식_변경.md)에 있다.

## 1. 한눈에 보기

```
① 주제 → ② 조사·출처 확인 → ③ 대본 → [승인 ①] → ④ 음성·자막 → ⑤ 이미지 → [이미지 확인] → ⑥ 영상화 → ⑦ 합성 → [승인 ②] → 다운로드
```

| 단계 | 하는 일 | 쓰는 도구 |
|---|---|---|
| ① 주제 | 직접 입력, 또는 "추천해 줘"로 후보 5개 | Gemini |
| ② 조사 | 출처 링크가 달린 자료 수집(**SNS·영상 사이트는 검색에서 처음부터 제외**, 결과 8개), **링크는 코드가 직접 접속해 확인**, 출처 본문(`detail`)도 보관 | Tavily |
| ③ 대본 | 확인된 출처만으로 장면별 대본(출처의 수치·원리·예시 활용). 근거 없는 장면이나 **출처 없는 수치**는 **코드가** 미확인 처리해 영상에서 뺌 | Gemini |
| 승인 ① | 출처와 대본을 보고 승인/반려(반려하면 의견을 반영해 다시 씀, 이전 버전은 보존) | 화면 |
| ④ 음성·자막 | 장면별 음성, 길이는 ffprobe로 측정, 자막 한 줄 18자 이하 | edge-tts |
| ⑤ 이미지 | 장면마다 AI 그림 또는 스톡 영상. 스톡은 Gemini가 후보 이미지를 보고 장면에 맞는 것을 고름(너무 어두운 후보는 제외, 한 영상 안에서 같은 영상 반복 금지) | Cloudflare, Pixabay, Gemini |
| 이미지 확인 | 장면별로 보고 마음에 안 드는 장면만 다시 만들기 | 화면 |
| ⑥ 영상화 | 그림을 장면 길이만큼 움직이는 클립으로 (확대 / 확대+오른쪽 이동 / 축소 / 확대+왼쪽 이동을 돌아가며) | ffmpeg |
| ⑦ 합성 | 1080×1920으로 맞춰 **0.3초 크로스페이드로** 이어 붙이고 음성·자막·화면 글자를 얹음 | ffmpeg |
| 승인 ② | 완성 영상을 보고 승인/반려(문제 단계를 골라 되돌아감) | 화면 |

외부 서비스가 막혀도 영상은 끝까지 나오게 **대체 수단**이 있다: 스톡이 안 맞으면 AI 그림 → 그림이 안 되면 글자 카드.

## 2. 설치 (Windows, PowerShell)

### 필요한 것
| 프로그램 | 확인 | 비고 |
|---|---|---|
| Python | `python --version` | **3.12.10에서 검증함.** 기획서는 3.13을 안내하지만 3.12에서 모두 동작했다 |
| ffmpeg·ffprobe | `ffmpeg -version`, `ffprobe -version` | PATH에 등록. **libass, libx264, libmp3lame 포함 빌드**(gyan.dev essentials 빌드로 확인) |
| Git | `git --version` | |

### 순서
```bash
git clone <저장소 주소>
cd app
python -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt
copy .env.example .env
```
> **프로젝트 폴더 경로를 짧게 둔다**(예: `D:\dev\app`). Windows 경로 길이 제한(260자) 때문에, 폴더가 깊으면 `pip install`이 `No such file or directory`로 실패한다(streamlit 안의 깊게 중첩된 파일이 원인이었다). 경로 39자에서는 정상 설치됐다. 설치는 약 3분 걸린다.

그다음 `.env`를 열어 아래 키를 **본인 이름으로 만든 계정**의 값으로 채운다. **`.env`는 절대 커밋하지 않는다**(`.gitignore`에 들어 있음). 채팅·이슈·스크린샷에도 키를 올리지 않는다.

| 키 | 어디서 | 메모 |
|---|---|---|
| `GEMINI_API_KEY` | [aistudio.google.com/apikey](https://aistudio.google.com/apikey) | 만 18세 이상. **무료 등급은 입력이 Google 제품 개선에 쓰일 수 있으니 공개된 주제만** 넣는다 |
| `TAVILY_API_KEY` | [tavily.com](https://tavily.com) | 월 1,000크레딧, 카드 불필요 |
| `PIXABAY_API_KEY` | [pixabay.com/api/docs](https://pixabay.com/api/docs/) | 가입 후 로그인한 상태에서 문서 페이지에 키가 표시됨 |
| `CLOUDFLARE_ACCOUNT_ID`, `CLOUDFLARE_API_TOKEN` | [dash.cloudflare.com](https://dash.cloudflare.com) | 토큰은 **Workers AI** 템플릿으로 만든다. 만든 직후 한 번만 보이니 바로 복사 |
| `YOUTUBE_API_KEY` | (선택) | 아직 쓰지 않는다 |

> **어떤 서비스에서도 결제 수단을 연결하지 않는다.** 한도가 차면 요금이 나오는 대신 요청이 실패한다(아래 6장).

### 글꼴 (자막·글자 카드)
`assets/fonts/`에 **Pretendard Regular, Bold**(`.otf`)를 넣는다. 없으면 다른 글꼴로 대체돼 모양이 달라진다.
> 글꼴 파일은 라이선스(SIL OFL) 확인 전이라 **저장소에 아직 올리지 않았다.** [공식 저장소](https://github.com/orioncactus/pretendard)에서 받는다.

## 3. 실행

### 화면으로 (권장)
```bash
.venv\Scripts\streamlit run ui/app.py
```
브라우저가 열린다(`http://localhost:8501`).

1. 왼쪽에서 **➕ 새 영상 만들기**
2. 주제를 입력하거나 **후보 5개 추천받기**
3. 영상 길이를 고르고 **▶ 시작** — 처음에는 **개발용(3장면·14초)**으로 시험하는 것을 권한다 (**표준 6장면·35초**가 기본, **최종용 9장면·60초**는 한도를 많이 쓴다)
4. **승인 ①** 출처(✅ 확인됨 / ⚠️ 사람이 확인)와 대본을 보고 승인 또는 반려(의견 필수)
5. **이미지 확인** 장면별 그림·스톡을 보고, 마음에 안 드는 장면만 체크해서 다시 만들거나, 괜찮으면 영상 만들기
6. **승인 ②** 완성 영상을 보고 승인(다운로드) 또는 반려(문제 단계 선택)

창을 닫아도 만들기는 계속된다. 다시 열면 같은 폴더의 진행 상황을 이어서 본다. 왼쪽 사이드바에서 **오늘의 무료 한도 사용량**도 볼 수 있다.

### 명령줄로
```bash
.venv\Scripts\python -m steps.s1_topic --new --topic "하루 10분 걷기의 효과"
```
위 명령이 새 실행 폴더를 만들고 경로를 알려 준다. 그 경로로 전체를 실행한다.
```bash
.venv\Scripts\python run.py --run outputs\20261021_1530_r001
```
승인이 필요한 곳(승인 ①, 이미지 확인, 승인 ②)에서는 **멈추고 종료**한다. 화면에서 승인한 뒤(또는 `common.approvals.record`로 기록한 뒤) 같은 명령을 다시 실행하면 이어서 진행한다.

| 옵션 | 뜻 |
|---|---|
| (없음) | 끝나지 않은 첫 단계부터 **이어서** 실행 |
| `--from voice` | `voice` 단계부터 **끝까지** 다시 실행 |
| `--only image` | `image` **한 단계만** 실행 (개발용) |
| `--scenes 9 --seconds 60` | 장면 수·길이 (`run_config.json`에 저장되어 다시 돌 때도 유지) |

> ⚠️ `--from`은 그 단계 **뒤의 모든 단계까지** 실행한다(외부 서비스 한도를 쓴다). 한 단계만 돌리려면 `--only`나 단계 파일을 직접 실행한다.

각 단계 파일은 혼자서도 실행된다(입력 폴더 안의 파일만 읽고 쓴다).
```bash
.venv\Scripts\python -m steps.s4_voice --run outputs\20261021_1530_r001
```
단계 파일: `s1_topic`, `s2_research`, `s3_script`, `s4_voice`, `s5_image`, `s6_motion`, `s7_compose`. 샘플 입력은 `samples/run_sample/`에 있다.

## 5. 이 프로그램의 약속 (코드가 지키는 것)

- **AI가 한 일은 코드가 한 번 더 확인한다.** 링크는 코드가 직접 접속해 판정하고(`ok`/`needs_review`/`fail`), 대본의 근거 id·형식·장면 수·수치는 코드가 검증한다. 장면 길이는 AI가 아니라 ffprobe가 잰 값이다. AI 응답 형식이 틀리면 한 번 다시 요청하고, 그래도 틀리면 오류로 멈춘다.
- **링크가 열린다(`ok`)는 내용이 맞다는 뜻이 아니다.** 내용이 주장을 뒷받침하는지는 승인 ①에서 **사람이 본다.** SNS·영상 사이트는 근거로 부적합해 자동으로 "사람이 확인"으로 낮춘다.
- **같은 요청은 다시 부르지 않는다.** 결과는 파일로 저장해 재사용한다(무료 한도 절약). 반려해서 다시 만들 때도 문제 장면만 다시 만든다.
- **키는 `.env`에만 둔다.** 코드·로그·화면에 키를 출력하지 않는다.
- **승인은 앱 사용자 본인이 누른다.** 승인해야만 다음 단계로 넘어간다.

## 6. 무료 한도

| 서비스 | 한도 (2026-10 확인) | 넘으면 |
|---|---|---|
| Cloudflare 그림 | 하루 10,000뉴런 ≈ 1024×1024 약 170장, 한국 시간 오전 9시 초기화 | 요청 실패 → 글자 카드로 대체 |
| Gemini | 모델당 분당 약 15회(하루 한도는 문서에 숫자 없음), 태평양시 자정 초기화 | 429 → 자동으로 기다렸다가 재시도 |
| Tavily | 월 1,000크레딧(검색 1회=1크레딧) | 다음 달까지 중단 |
| Pixabay | 60초에 100회, 검색 결과 24시간 저장 의무, 출처 표시 | 429 |
| edge-tts | 키 없는 비공식 도구라 공식 한도 표기 없음, 서비스 쪽 변경으로 막힐 수 있음 | 음성 생성 실패 |

영상 1편(표준 6장면)은 대략 Cloudflare 그림 2~3장, Gemini 3~5회, Tavily 1회, Pixabay 검색 수 회를 쓴다.

### 60초(9장면) 영상 실측 — 8GB PC (i5-6200U, 4코어, RAM 7.9GB 중 여유 1.7GB)
`--scenes 9 --seconds 60`으로 주제 입력부터 승인 ②까지 끝까지 돌린 결과(2026-10-20). 완성 영상은 **54.6초**(음성 길이에 따라 60초 안팎), 1080×1920, 17.5MB.

| 단계 | 소요 시간 | 최대 메모리 |
|---|---|---|
| ② 조사 (출처 8개 링크 확인 포함) | 약 12초 | 약 90MB |
| ③ 대본 (Gemini 1회) | 약 10초 | 약 90MB |
| ④ 음성·자막 (9장면) | 약 17초 | 약 100MB |
| ⑤ 이미지 (스톡 6개 + AI 그림 3장, Gemini 이미지 판단 6회) | 약 80초 | 약 100MB |
| ⑥ 영상화 (AI 그림 3개) | 약 20초 | 약 350MB |
| ⑦ 합성 (클립 정리 + 0.3초 크로스페이드 + 최종 인코딩) | 약 79초 | 약 390MB |
| **합계 (사람이 승인을 기다리는 시간 제외)** | **약 3.6분** | **약 400MB** |

- **외부 호출:** Gemini 약 8회(대본 1 + 이미지 판단 7 — 한 장면을 다시 만든 것 포함), Cloudflare 그림 3장, Tavily 1회, Pixabay 검색 약 6회. 모두 무료 한도의 일부이며, 한 시간 안에 여러 편 만들어도 한도에 걸리지 않는다.
- **⑦ 합성이 처음에는 최대 1.4GB, 약 2.7분이었다.** ① `-shortest`가 영상 프레임을 쌓아 메모리를 키웠고(`-t`로 대체해 380MB), ② 가로 스톡의 흐린 배경을 큰 크기에서 처리하느라 느렸다(작은 크기에서 흐리고 키워 약 40% 단축, 중간 클립은 `ultrafast`).
- 대본이 길수록 그림 장면 수가 늘어 ⑤가 가장 오래 걸린다(그림 1장 약 3초, 스톡 1개는 Gemini 판단 때문에 약 8~10초).

**한도가 차도 요금은 나오지 않는다**(결제 수단을 연결하지 않았으므로). 화면에서는 오류로 멈췄다가 **"이어서 다시 실행"**으로 이어 갈 수 있다.
사이드바의 사용량은 **이 PC의 이 앱이 보낸 호출만 센 추정치**다. 정확한 값은 각 서비스 대시보드에서 확인한다.

## 7. 문제 해결

| 증상 | 원인과 해결 |
|---|---|
| `pip install`이 `No such file or directory: …\streamlit\.agents\…`로 실패한다 | Windows 경로 길이 제한. 프로젝트를 더 짧은 경로로 옮기고 `.venv`를 지운 뒤 다시 설치 |
| 화면을 고쳤는데 `AttributeError`가 난다 | 켜져 있는 서버는 옛 모듈을 계속 쓴다. 서버를 `Ctrl+C`로 끄고 다시 실행. (`steps/` 안 파일은 별도 프로세스로 돌아 서버를 안 꺼도 반영된다) |
| "이미 이 폴더에서 run.py가 실행 중입니다" | 같은 폴더에서 이미 돌고 있다. 기다린다. 비정상 종료로 남은 잠금은 자동으로 치운다 |
| ❌ 오류 화면 | 원인 메시지를 보고 잠시 뒤 **이어서 다시 실행**. 끝난 단계는 다시 만들지 않는다 |
| 자막이 안 보인다 | `assets/fonts`에 Pretendard가 있는지 확인. 자막 위치·크기는 `steps/s7_compose.py`의 `SUB_STYLE` — **숫자가 픽셀이 아니라 384×288 기준**이라 값을 크게 넣으면 화면 밖으로 밀려 안 보인다 |
| 엉뚱한 스톡 영상이 나온다 | 승인 전 **이미지 확인**에서 그 장면을 체크해 다시 만든다(이미 본 영상은 제외하고 다음 후보를 고른다) |
| 그림이 이상하다 | 이미지 확인에서 다시 만들기. 같은 설명으로도 매번 다른 그림이 나온다 |
| 반려했는데 같은 결과가 나온다 | 음성·움직임·합성은 입력이 같으면 저장된 결과를 재사용한다(알려진 한계, 8장). 그림·스톡·대본은 바뀐다 |
| 429 / 한도 초과 | 위 6장. Gemini는 분당 한도라 잠시 뒤 재시도, Cloudflare는 한국 시간 오전 9시에 초기화 |
| 주제 파일이 깨져 보인다 | `topic.txt`는 UTF-8 한 줄. 메모장으로 저장해도 BOM은 자동으로 무시한다 |

## 8. 알려진 한계

- 스톡 영상 선택은 대표 이미지 **1장**만 보고 판단한다(영상 전체의 움직임, 처음 몇 초만 어두운 영상은 못 잡을 수 있다). 후보 5개 안에 정답이 없으면 AI 그림으로 바뀐다. 주제와 정확히 맞는 영상이 없으면 "분위기가 비슷한" 영상이 선택될 수 있어 **이미지 확인에서 사람이 봐야 한다.**
- AI 그림 품질은 대본의 그림 설명에 좌우된다. 사람 손·글자가 나오는 장면은 스톡을 우선하도록 안내하지만 완벽하지 않다.
- 음성·움직임·합성 단계는 **장면 단위 재생성이 없다**(입력이 같으면 같은 결과 재사용). 그림·스톡·대본은 가능하다.
- 자막 시간은 글자 수에 비례한 추정이라 실제 발음과 조금 어긋날 수 있다. 장면 전환(0.3초 크로스페이드) 때문에 새 장면이 완전히 보이는 시점이 음성보다 약 0.3초 늦다.
- 영상 길이는 Gemini가 쓴 대사 길이에 따라 정해져 **목표(60초)보다 짧게 나올 수 있다**(실측 54.6초).
- Gemini가 가끔 JSON 형식을 어겨(배열로 답하는 등) 한 번 다시 요청한다. 코드가 흔한 형식 오류는 고쳐 받지만, 끝내 실패하면 `script_failed_response.json`에 원본 응답을 남기고 멈춘다.
- 인기 영상 참고(YouTube)는 아직 구현하지 않았다(`popular_refs`는 빈 목록).
- 시험은 아직 **저장소에 자동 시험 파일이 없다**(개발 중 임시 스크립트로 확인). 단계별 시험 입력은 `samples/`, 서비스별 시험은 `trials/`.
- `requirements.txt`의 `moviepy`는 현재 **쓰이지 않는다**(합성은 ffmpeg만 사용). 정리할지 팀에서 정한다.

## 9. 팀 작업 규칙 (요약)

- 각자 자기 폴더·가지에서 작업하고 Pull Request → 팀원 1명이 "돌아가는지" 돌려 보고 합친다.
- 공용 파일 형식은 **2주차 말 팀 비교 뒤 확정**하고, 그 뒤에는 바꾸기 전에 채널에 먼저 알린다.
- 막히면 30분 안에 화면 캡처와 함께 채널에 올린다.
- 커밋 메시지는 한국어로 짧게. API 키·`.env`·`outputs/`는 올리지 않는다.
