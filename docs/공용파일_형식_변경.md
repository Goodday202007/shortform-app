# 공용 파일 형식 — 현재 형식과 변경 목록

> 기준: 2026-10-20, 코드 커밋 `1b923dc`. CLAUDE.md의 "공용 파일 형식(초안)"과 비교해 **무엇이 바뀌었고 새로 생겼는지** 정리했다.
> 2주차 말 팀 비교 때 이 문서를 기준으로 각자의 형식과 맞춰 보고, 확정 뒤에는 바꾸기 전에 채널에 먼저 알린다.
> 예시는 실제 실행 결과(`outputs/` 안의 파일)에서 가져왔다. 긴 글은 `…`로 줄였다.

## 2. 파이프라인 순서 (바뀐 점 포함)

```
① topic → ② research → ③ script → [승인 ①] → ④ voice → ⑤ image → [이미지 확인] → ⑥ motion → ⑦ compose → [승인 ②]
```

**기획서와 다른 점 (팀이 알아야 할 것)**
1. **승인이 3개다.** 기획서의 승인 ①②에 더해 ⑤ 뒤에 **이미지 확인**(사용자 요청)을 넣었다. 장면별로 그림·스톡을 보고, 마음에 안 드는 장면만 다시 만든다.
2. **스톡 영상 선택에 Gemini를 쓴다.** 태그로 후보 5개를 추린 뒤, 후보의 공개 썸네일을 Gemini가 보고 장면에 맞는 것을 고른다(없으면 AI 그림으로 대체). 태그만으로는 "사람이 달리는지 개가 달리는지" 구별할 수 없어서였다.
3. **대본의 화면 글자(`screen_text`)를 영상 위쪽에 얹는다.** 글자 카드 장면은 카드에 이미 있어 제외.
4. **글자 카드(`text_card`)는 최후의 대체 수단 전용**이다. ③이 만들지 않고, ⑤에서 스톡·그림이 모두 실패할 때만 쓴다.
5. **합성은 ffmpeg만 쓴다.** MoviePy는 설치돼 있지만 코드에서 쓰지 않는다.
6. 영상 길이 선택: 개발용(3장면·14초) / **표준(6장면·35초, 기본)** / 최종용(9장면·60초).

## 3. 파일별 형식

### 3.1 실행 폴더
`outputs/날짜_시각_r번호/` — 예: `20261019_2256_r007`. **한글을 넣지 않는다.** 번호는 날짜가 바뀌어도 이어진다(기존 최댓값+1).
주제는 `topic.txt`에 적는다. `outputs/`는 Git에 올리지 않는다(`.gitignore`).

### 3.2 `topic.txt`
한 줄, UTF-8(BOM 없음), 100자 이하. 읽을 때는 BOM이 있어도 무시한다(`utf-8-sig`) — 메모장 저장 대비.
```
달리기 효과
```

### 3.3 `topic_candidates.json` ★새 파일 (① 추천을 쓸 때만)
```json
{ "field": "건강",
  "candidates": [ { "no": 1, "topic": "아침 공복 물 한 잔이 신진대사에 미치는 영향",
                    "why": "수분 섭취와 대사 촉진에 관한 연구가 명확함" } ] }
```
후보는 정확히 5개, 주제 40자 이하, 서로 달라야 한다(코드가 검증).

### 3.4 `research.json` (② → ③, 승인 ①에서 사람이 봄)
```json
{ "topic": "달리기 효과",
  "summary": "…",                       // Tavily가 준 요약. 문장 중간에서 끊기거나 영어일 수 있음 — 대본은 쓰지 않는다
  "sources": [
    { "id": "r1",
      "claim": "두뇌에도 효과가 있다. 달리기와 같은 유산소 운동은 뇌에 혈액을 많이 공급하게 해 …",
      "url": "https://namu.wiki/w/…",
      "link_status": "ok",              // ok | needs_review | fail
      "link_ok": true,                  // link_status == "ok" 일 때만 true
      "detail": "두뇌에도 효과가 있다. 달리기와 같은 …(최대 900자)" },     // ★추가, 선택
    { "id": "r4", "claim": "…", "url": "https://www.youtube.com/watch?v=…",
      "link_status": "needs_review", "link_ok": false,
      "note": "SNS·영상 사이트는 근거로 부적합할 수 있어 사람이 확인" }      // ★추가, 선택
  ],
  "popular_refs": [] }                  // YouTube 인기 영상 참고: 아직 구현하지 않아 항상 빈 목록
```
- `claim`: Tavily 요약문 앞쪽 문장(최대 200자). AI가 다듬지 않는다.
- `detail`: 본문이 `claim`보다 충분히 길 때만 있다. ③ 대본이 수치·원리·예시를 찾는 원문.
- **링크 판정은 코드가 한다**: 200대=`ok`, 403/429 등 봇 차단=`needs_review`, 404·5xx·연결 실패=`fail`. instagram·youtube·facebook·tiktok·x 도메인은 200이어도 `needs_review`로 낮추고 `note`를 단다.
- **주의**: `ok`는 "링크가 열린다"일 뿐 "내용이 주장을 뒷받침한다"가 아니다. 그건 승인 ①에서 사람이 본다.

### 3.5 `script_vN.json` (③ → ④⑤⑦, 승인 ①에서 사람이 봄)
```json
{ "version": 2,
  "title": "달리기를 하면 뇌가 좋아지는 이유",
  "feedback": null,                     // 반려 의견을 반영해 다시 쓴 버전이면 그 의견
  "scenes": [
    { "no": 2,
      "screen_text": "뇌 혈액 순환 개선",
      "narration": "유산소 운동은 뇌에 피를 많이 보내 신경세포의 결합 능력을 키워줍니다.",
      "source_ids": ["r1"],
      "visual": "a person running along a green park trail on a sunny day",
      "stock_query": "",                // ★추가: stock 장면은 영어 키워드 1~5개(예: "runner running park"), 그 외는 ""
      "type": "ai_image",               // ai_image | stock  (text_card 는 ③이 더 만들지 않음)
      "unverified": false } ] }
```
- **버전은 덮어쓰지 않는다**: `script_v1.json`, `script_v2.json`… 반려할 때마다 다음 번호가 생긴다.
- `visual`: AI 그림용 영어 설명(구체적인 일상 장면). `stock` 장면에서는 스톡을 못 찾을 때 AI가 대신 그릴 설명.
- `unverified: true`인 장면은 **영상에서 뺀다**(④~⑦이 건너뜀). 판정은 코드가 한다:
  - 사실을 주장하는데(`makes_claim`) 확인된 출처가 없음, 또는
  - 퍼센트이거나 **주제에 없는 숫자**("시속 8km" 등)가 출처 없이 나옴.
- `source_ids`는 `link_ok: true`인 출처 id만 허용한다(그 밖의 id는 코드가 지운다).
- 코드가 강제하는 것: 장면 수, `type` 값, `stock_query` 형식, `stock`이 전체의 2/3를 넘으면 초과분을 `ai_image`로 변환(첫·마지막 장면은 가급적 유지), `text_card` → `ai_image` 변환.
- Gemini가 답할 때만 쓰는 `makes_claim`은 **저장하지 않는다**.

### 3.6 `approvals.json` (화면 → run.py, 항목을 쌓기만 한다)
```json
[ { "stage": 1, "result": "rejected", "return_to": "script",
    "comment": "2번 장면의 22%는 최대치입니다…", "at": "2026-10-19T22:57:29.267119+09:00" },
  { "stage": 3, "result": "rejected", "return_to": "image", "comment": "", "scenes": [2],
    "at": "2026-10-20T10:03:11.5+09:00" },
  { "stage": 2, "result": "approved", "return_to": null, "comment": "", "at": "…" } ]
```
| stage | 이름 | 실행 순서 | 심사 대상 | 반려 시 `return_to` |
|---|---|---|---|---|
| 1 | 승인 ① 출처·대본 | 1번째 | 가장 최신 `script_vN.json` | `script`만 |
| 3 | **이미지 확인** ★ | 2번째 | `scenes/_image_meta.json` | `image`만 (`scenes` 필수, 의견 선택) |
| 2 | 승인 ② 완성 영상 | 3번째 | `final.mp4` | `script`·`voice`·`image`·`motion`·`compose` |

- 번호가 실행 순서와 다른 것은 **기록 호환** 때문이다(승인 ②를 2로 유지, 나중에 생긴 이미지 확인을 3으로).
- **유효 규칙**: 기록 시각이 심사 대상 파일의 수정 시각보다 **뒤**여야 유효하다. 그 뒤에 대본·그림·영상이 새로 만들어졌다면 옛 판정은 무효이고 다시 승인을 기다린다.
- 반려는 의견(`comment`) 필수. 이미지 확인만 예외(대신 `scenes`가 필수).
- `scenes`: 다시 만들 장면 번호(정렬·중복 제거). 이미지 확인과 승인 ②의 `image` 반려는 **실제 재생성**에 쓰이고, 다른 단계 반려에서는 아직 기록만 한다.

### 3.7 `status.json` (run.py → 화면)
```json
{ "current": "approval_images", "done": ["topic","research","script","approval1","voice","image"],
  "error": null, "state": "waiting", "pid": null }
```
- `state`(★추가): `running` | `waiting`(승인 대기) | `done` | `error` | `idle`. `pid`(★추가): 실행 중인 `run.py` 프로세스 번호.
- 단계 이름: `topic research script approval1 voice image approval_images motion compose approval2`.
- 화면은 이 파일만 읽고, 실제로 도는지는 `run.lock`의 프로세스가 살아 있는지로 판단한다(비정상 종료 대비).
- 이미지 확인이 생기기 전에 끝난 폴더(`done`에 `approval_images` 없음)도 되감지 않는다.

### 3.8 `run_config.json` ★새 파일
```json
{ "scenes": 6, "seconds": 35 }
```
영상 길이 설정. 반려로 다시 돌 때도 같은 값을 쓴다. 한국어 음성은 1초에 약 6.5자라 길이가 곧 대본의 상세함이다.

### 3.9 `timings.json` (④ → ⑤⑥⑦) — 변화 없음
```json
[ { "no": 1, "start": 0.0, "duration": 6.096 } ]
```
`duration`은 AI가 아니라 **ffprobe로 잰 mp3 길이**다. `unverified` 장면은 목록에 없다(번호가 비어 있을 수 있음).

### 3.10 음성·자막 (④)
- `voice/sNN.mp3`(장면별), `voice/_meta.json`(대사 해시 — 바뀐 장면만 다시 만듦), `voice.mp3`(이어 붙인 것), `subtitle.srt`.
- 자막: 한 줄 18자 이하, 장면 시간 안에서 글자 수에 비례해 시간 배분(단어별 정밀 싱크 아님).

### 3.11 `scenes/` (⑤⑥)
| 파일 | 설명 |
|---|---|
| `sNN.png` | AI 그림(1024×1024) 또는 글자 카드(1080×1920) |
| `sNN.mp4` | **png가 있으면** ⑥이 만든 움직이는 클립(1080×1920, 장면 길이 + 전환용 여분 12프레임). **png가 없으면** ⑤가 받은 스톡 원본(가로일 수 있음) |
| `_image_meta.json` ★ | 장면별 `{digest, kind("png"/"mp4"), used("ai_image"/"stock"/"text_card"), fallback, stock_id}` — 같은 입력이면 재사용, `fallback: true`면 다음 실행에 다시 시도 |
| `credits.json` ★ | 스톡 장면의 출처 표시 `{"s01": {"credit": "Video by … from Pixabay", "page_url": "…"}}` — **Pixabay가 출처 표시를 요청**하므로 승인 ②·완료 화면에 보여 준다 |
| `_variants.json` ★ | 다시 만들기 기록 `{"s02": {"variant": 1, "exclude": [스톡 id…]}}` — 변형 번호가 바뀐 장면만 다른 결과로 재생성 |
| `_motion_meta.json` | ⑥ 클립의 입력 해시(그림·길이·움직임·필터 버전) |

"png가 있으면 mp4는 ⑥ 결과"라는 규칙 때문에, **⑥은 대본의 `type`이 아니라 png 존재 여부로** 처리한다(스톡이 그림으로 대체돼도 안전).

### 3.12 합성 (⑦)
`compose/`(중간 조각, 지워도 됨 — 장면마다 `sNN_head/body/tail.mp4`와 장면 사이 크로스페이드 `xNN.mp4`, 합성할 때마다 비우고 다시 만든다), `titles.ass`(★ 화면 글자 자막, 1080×1920 픽셀 좌표), `final.mp4`(1080×1920, 30fps, h264+aac).

### 3.13 실행 관리 파일
`run.log`(진행 기록, 추가만), `run.lock`(실행 중인 프로세스 번호, 동시 실행 방지).

### 3.14 공용 저장본과 사용량 (실행 폴더 밖)
- `outputs/_cache/` — 같은 요청을 다시 부르지 않기 위한 저장본: `images/`(그림), `videos/`(스톡 영상), `pixabay/`(검색, 24시간 유효 — Pixabay 규칙), `tavily/`(검색), `vision/`(Gemini 이미지 판단).
- `outputs/_usage.jsonl` ★ — 실제로 외부 서비스에 요청이 나간 순간의 기록. 한 줄: `{"t": "ISO 시각", "service": "cloudflare|gemini|tavily|pixabay", "n": 1, "ok": true, "note": "…", "est": false}`. `est: true`는 기록 기능 이전 호출을 저장 파일 시각으로 추정한 것.

## 5. 팀 비교 때 확인할 것
1. **승인 단계 수와 위치**: 우리는 3개(①, 이미지 확인, ②)다. 다른 팀원 안과 맞는가?
2. **`type` 값 집합**: `ai_image | stock | text_card`에 다른 방식(예: AI 영상 `ai_video`)이 필요한가?
3. **`stock_query`·`detail`·`note`**: 필수로 둘지 선택으로 둘지.
4. **`unverified`·`source_ids` 판정 규칙**(수치 규칙 포함)을 공통으로 쓸지.
5. **`scenes/` 안의 `png`/`mp4` 구분 규칙**과 `credits.json`(출처 표시)을 공용으로 둘지.
6. **`status.json`의 `state`/`pid`와 `run.lock`** 방식을 공용 약속으로 둘지.
7. `approvals.json`의 **유효 규칙(파일 수정 시각 비교)**이 팀 저장 방식(공유 폴더)에서도 안전한지 — 파일 시각이 바뀌는 복사·동기화에서는 판정이 어긋날 수 있다.
