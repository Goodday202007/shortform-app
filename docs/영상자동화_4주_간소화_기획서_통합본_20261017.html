한눈에 보기

목표. 주제를 넣으면 AI가 조사와 대본을 쓰고, 사람이 확인·승인하면 숏폼 영상 1편이 나오는 자동화 프로그램을 4명이 돈을 한 푼도 쓰지 않고 만든다.

  • 먼저 각자 만들어 본다. 4명이 작은 영상 자동화 프로그램을 한 번씩 직접 만들어 본 뒤, 서로 비교하며 합친다
  • 역할은 만들어 본 뒤에 정한다. 각자 어디에 강하고 무엇을 하고 싶은지 알고 나서 나눈다
  • 무료로만 만든다. 무료 프로그램·무료 AI·무료 API만 쓰고 결제 수단은 어느 서비스에도 연결하지 않는다. 한도가 차면 돈을 내는 대신 멈추거나 다른 무료 수단으로 바꾼다
  • 두 가지 확인을 구분한다. 프로젝트를 만드는 동안에는 팀원끼리 서로 더블체크하고(Pull Request 검토, 시험 영상 교차 점검), 완성된 앱에서는 영상을 만드는 사용자 본인이 승인 ①②를 눌러 다음 단계로 넘어간다
  • AI가 한 일은 코드가 한 번 더 확인한다. 출처 링크, 대본의 근거, 장면 길이는 AI에게 맡기지 않고 파이썬 코드로 검사한다 (팀원 리서치 반영)

진행 순서. 각자 리서치 → 모임에서 이야기(10/14 수) → 기획서 완성(10/17 토) → 각자 만들어 보기(10/21 수) → 비교하고 역할 분담 → 합쳐서 완성(3~4주차)

프로그램이 하는 일

사람 눈에는 8단계다. 기존 ④(음성·영상)를 ④ 음성·자막 / ⑤ 이미지 생성 / ⑥ 이미지 영상화 / ⑦ 영상 합성으로 나누었다. 한 단계가 끝나면 파일이 생기고 다음 단계가 그 파일을 읽는다. ⑤는 대본만 있으면 되어서 ④와 동시에 진행할 수 있고, ⑥은 장면 길이(④의 timings.json)가 필요해서 ④ 뒤에 온다. 실행은 run.py가 맡아 단계 순서대로 돌리고, 지금 어느 단계인지 status.json에 적어 두어 중간에 멈춰도 그 단계부터 이어서 돌린다.

단계하는 일쓰는 도구만들어지는 파일
① 주제 정하기직접 입력하거나 "추천해 줘"를 누르면 숏폼에 맞는 후보 5개(JSON)를 보여 준다. 분야별 인기 영상 제목을 함께 넣어 요청한다Streamlit, Gemini, YouTube Data APItopic.txt
② 조사·출처 확인 · ③ 장면별 대본출처 링크가 달린 조사(주장 한 줄 + URL)를 받는다. 코드가 각 URL에 접속해 응답 200을 확인하고(선택: 본문에 핵심 단어가 있는지도 검사) 통과한 항목만 link_ok: true로 둔다. 확인된 항목만 넘겨 장면별 대본을 쓰게 하고 장면마다 근거 source_ids를 달게 한다. 코드가 "모든 장면의 근거가 확인된 목록 안에 있는지" 검사해 아니면 그 장면을 "미확인"으로 표시해 뺀다Tavily, YouTube Data API, Gemini, 파이썬(requests)research.json, script_v1.json
③ 승인 ①앱 사용자가 출처와 대본을 보고 직접 승인하거나 반려한다. 승인하면 다음 단계로 넘어가고, 반려하면 의견을 적는다Streamlit승인 기록
④ 음성·자막장면마다 따로 음성을 만든다. 장면별 mp3 길이를 ffprobe로 재서 timings.json에 적고 이어 붙여 voice.mp3를 만든다. 자막은 edge-tts의 srt를 장면 시작 시간에 맞춰 합치고 한 줄 15~18자로 코드가 나눈다edge-tts, ffprobe, 파이썬voice.mp3, timings.json, subtitle.srt
⑤ 이미지 생성 (신규)장면마다 그림 설명(visual)을 영어 그림 설명으로 바꿔 AI 그림 1장씩 만든다. 사람·손·글자가 나오는 장면 등은 스톡 영상을 검색해 받는다(이 장면은 ⑥을 건너뛴다). 끝나면 장면 이미지를 한 화면에 모아 보여 준다Gemini, Cloudflare FLUX, Pixabayscenes/s01.png … (또는 s01.mp4)
⑥ 이미지 영상화 (신규)장면 그림을 장면 길이(timings.json)만큼의 클립으로 만든다. 기본은 ffmpeg로 천천히 확대·이동. 핵심 장면 1~3개만 Colab에서 Wan 2.2로 실제 움직이는 클립을 시험한다(고도화)ffmpeg, (Colab Wan 2.2)scenes/s01.mp4 …
⑦ 영상 합성각 클립을 1080×1920으로 자르고 이어 붙인 뒤 음성과 자막(Pretendard)을 얹는다ffmpeg, MoviePyfinal.mp4
⑧ 승인 ② · 다운로드완성 영상을 보고 승인한 뒤 내려받는다. 반려하면 되돌아갈 단계를 고른다Streamlitfinal.mp4, 승인 기록

승인 ①②는 앱 사용자가 직접 누른다. 앱은 영상을 만드는 사용자에게 출처와 대본(①), 완성 영상(②)을 보여 주고, 사용자가 승인해야만 다음 단계로 넘어간다. 앱은 승인자를 따로 지정하지 않고 다른 사람을 요구하지도 않는다. 팀 프로젝트의 "서로 확인하는 과정"은 앱 기능이 아니라 개발 과정의 약속이며, 아래 "팀 규칙"에 적었다.

반려하면 어디로 돌아가나. 승인 결과와 돌아갈 단계를 기록하고, 고른 단계부터 다시 실행한다. 장면 단위로 파일을 남겨 문제 장면만 다시 만든다.

상황되돌아가는 곳방법
승인 ① 반려 (출처·대본 문제)③ 대본이전 대본 + 사람이 쓴 수정 의견을 AI에 넘겨 고쳐 쓴다. 덮어쓰지 않고 script_v1.json, script_v2.json…으로 남겨 무엇이 바뀌었는지 비교한다
승인 ② 반려 — 내용·대본 문제③ 대본위와 같고 ④~⑦을 다시 실행한다
승인 ② 반려 — 음성·자막 문제④ 음성·자막문제 장면의 음성만 다시 만들고 ⑥·⑦을 다시 실행한다
승인 ② 반려 — 그림이 이상함⑤ 이미지 생성문제 장면의 그림만 다시 만들고 ⑥·⑦을 다시 실행한다

장면 영상 만드는 방법 (⑤⑥단계)

장면 영상은 대본의 장면마다 깔 화면을 하나씩 만드는 일이다. 화면을 얻는 길은 세 가지이고, 아래 표에 자세히 적었다.

  • 1번 스톡 영상: 이미 있는 영상을 받아 쓴다. 쉽지만 대본과 딱 맞는 영상이 없을 수 있다
  • 2번 AI 그림 + 움직임 (기본): AI가 그림을 그리고, 그 그림을 천천히 확대해서 영상처럼 만든다. 대본에 맞는 장면을 만들 수 있다
  • 3번 AI 영상 (고도화): 그림이 실제로 움직이는 영상을 만든다. 느리고 불안정해서 여유가 있을 때만 한다

언제 무엇을 쓰나. 기본은 2번이다. AI는 사람·손·글자가 나오는 그림을 자주 틀리므로, 그런 장면만 1번으로 바꿔 쓴다. 1번은 ⑤에서 영상을 받으면 끝나서 ⑥을 건너뛰고, 2번은 ⑤에서 그림을 만든 뒤 ⑥에서 움직임을 준다. 스톡 영상 공급처(Pixabay)는 아직 확인 전이므로, 안 되거나 맞는 영상이 없으면 그 장면을 AI 그림(2번)으로 자동으로 바꾼다(사람이 고르는 수동 작업은 하지 않는다). 그래서 스톡이 막혀도 영상은 끝까지 나온다. 장면 설명은 Gemini가 영어 검색어(스톡용)와 영어 그림 설명(AI 그림용)으로 바꿔 주면 결과가 훨씬 좋다.

방법어떻게 (단계)좋은 점한계
1. 스톡 영상 (보완)⑤에서 영어 검색어로 Pixabay에서 영상을 검색해 받고 ⑦에서 9:16으로 자른다. ⑥은 건너뛴다. 출처 표시를 한다진짜 영상이라 가장 빨리 한 편이 나온다. GPU 불필요대본과 딱 맞는 영상이 없을 수 있다. Pexels는 신규 키 발급 중단, Pixabay는 키 발급과 약관을 1주차에 확인한다
2. AI 그림 + 움직임 (기본)⑤에서 Cloudflare FLUX로 그림 1장, ⑥에서 ffmpeg로 천천히 확대·이동대본에 딱 맞는 장면을 만들 수 있다. 1024×1024 기준 하루 약 170장 무료. GPU 불필요움직임이 단순하다. 그림 속 글자가 틀릴 수 있어 글자는 자막으로 얹는다
3. AI 영상 생성 (고도화)⑤의 그림을 ⑥에서 Colab 무료 GPU의 Wan 2.2로 짧은 클립으로 만든다 (노트북 코드 셀 실행)그림이 실제로 움직인다480p 약 5초 수준이고 GPU 배정이 보장되지 않는다. 핵심 장면 1~3개에만 쓴다

1~2주차에 네 명이 각자 다른 방법(스톡 / AI 그림 / AI 영상)을 시험해 오고 2주차 말 비교 시연에서 비용·품질·소요 시간을 견주어 기본 방법을 확정한다. 장면마다 type(stock / ai_image)을 정해 두면 한 영상에서 두 방법을 섞을 수 있다. Gemini의 이미지 생성(나노 바나나)은 무료 등급이 "사용 불가"라 뺐다(10/14 확인). 영상 1편에는 그림 6~10장만 쓰고, 만든 그림은 저장해 재사용한다.

역할 후보 조각과 공용 파일 약속

역할은 지금 정하지 않고 2주차 말 비교 뒤에 정한다. 조각은 5개이고 4명이 나누므로 ⑤⑥ 이미지와 ⑦ 합성은 한 사람이 맡을 수도 있다. 시험 주제 3개, 평가표, 사용 설명서, 발표 자료, 주간 기록은 조각과 별개로 4명이 나눠 맡는다.

조각 사이의 약속. 조각끼리는 아래 파일로만 주고받는다. 형식은 2주차 말에 각자 만든 것을 비교해 확정하고, 그 뒤에는 바꾸기 전에 채널에 먼저 알린다.

파일들어 있는 것

script.json영상 제목, 장면 목록(장면 번호, 화면에 띄울 글자, 읽을 대본, 근거 source_ids, 그림 설명 visual, 소재 종류 type), 미확인 장면 표시
scenes/장면별 그림(s01.png)과 클립(s01.mp4). 장면 단위로 남겨 일부만 다시 만들 수 있게 한다
voice.mp3 + timings.json + subtitle.srt이어 붙인 음성, 장면별 시작·길이, 시간표가 붙은 자막

저장. 실행마다 폴더 하나(outputs/날짜_주제/)를 만들어 영상, 대본 버전들, research.json, timings.json, scenes/, 승인 기록(누가·언제·결과·의견)을 모두 넣는다. 승인은 영상을 만든 사용자가 같은 화면에서 하므로 승인용 공유 폴더나 배포는 필요 없다. 팀원끼리 시험 영상을 돌려 볼 때만 폴더를 공유한다.

PC 사양별 할 수 있는 일

AI 두뇌, 조사, 그림, 음성은 클라우드의 무료 서비스가 맡기 때문에 PC가 약해도 대부분의 조각을 만들 수 있다. PC가 힘을 쓰는 곳은 ⑥⑦(영상화·합성)뿐이다. 이 정도 합성은 8~16GB PC에서도 돌아간다.

PC할 수 있는 일피할 일
제안자 (RAM 32GB, GTX 1660 Ti VRAM 6GB)최종 영상 합성 전체, 모든 조각 개발로컬 AI 영상 생성(VRAM 8GB 미만이라 3번 방법은 Colab으로만)
팀원 (RAM 16GB)화면·승인, 대본·음성 개발, 짧은 영상 합성 시험긴 영상 합성, 큰 Whisper 모델
팀원 2명 (RAM 8GB)대본·음성·화면처럼 클라우드를 부르는 조각, 10~15초 영상 합성 시험60초 영상 합성, 로컬 Whisper

팀원 PC의 그래픽 카드 종류와 나머지 8GB PC의 사양은 아직 모른다. 수요일 모임에서 확인한다.

개발 도구와 작업 방식

  • 내 PC에 까는 것(모두 무료): Python 3.13.16(또는 3.14.8), ffmpeg 9.0.2, VS Code, GitHub Desktop, Claude Code. 파이썬 도구는 pip로 깐다: streamlit 1.65.0, moviepy 2.2.1, edge-tts 7.3.1
  • 계정은 각자 본인 이름으로 만든다: Google AI Studio(Gemini), Tavily, Pixabay, Cloudflare, GitHub. 키는 각자 PC의 .env 파일에만 둔다
  • 프로그램 안의 AI는 Gemini 무료 등급이 기본이다. Claude API를 프로그램에서 직접 부르면 구독과 별개로 요금이 든다. Claude Code의 claude -p 명령은 구독 한도 안에서 쓸 수 있다는 공식 안내(2026-10-07)가 있어 대체 수단으로 둔다
  • Gemini 무료 등급에서는 입력한 내용이 Google 제품 개선에 쓰일 수 있으므로 공개된 주제와 공개 자료만 넣는다. YouTube 키는 4명이 같은 프로젝트면 하루 한도를 함께 쓰며, 한도를 늘리려고 프로젝트를 여러 개 만드는 것은 약관 위반이라 하지 않는다

4주 일정

시작 전에 각자 조사해 이야기하고, 1~2주차에는 각자 만들어 보고, 2주차 말에 비교해 역할을 정하고, 3~4주차에 합쳐 완성한다. 매주 말 점검에서 통과 기준을 못 채우면 다음 주 범위를 줄인다.

주차하는 일주말 점검 통과 기준
시작 전 (10/14 수)각자 리서치. 각자 PC 사양(그래픽 카드 포함) 확인큰 흐름(8단계), "각자 만들어 보기", 무료로만 만든다는 원칙에 합의
1주차 설치·각자 시작설치 확인, GitHub 연습 Pull Request, 무료 계정과 키(Gemini, Tavily, Pixabay, Cloudflare). Pixabay 키 발급과 약관 확인(Pexels는 신규 키 중단). 도구별 시험 파일: 음성 1, AI 그림 1, 스톡 영상 1, 대본 1. 각자 가짜 샘플 파일로 8단계 중 되는 것부터 만든다. YouTube 키 확인4명 모두 설치·가입을 마치고, 음성·이미지·대본 시험 파일이 있고, 한 단계 이상 돌아간다
2주차 각자 완성·비교각자 주제 입력부터 짧은 영상까지 한 줄기를 끝까지 만든다(품질은 낮아도 됨). 장면 영상은 사람마다 다른 방법을 시험한다. 주말에 시연·비교하고 역할·공용 파일 형식·이미지 기본 방법·저장 방식을 정한다시연을 마치고(못 간 사람은 어디까지 갔는지 공유) 역할이 정해진다
3주차 합치기정한 역할대로 조각을 다듬고 run.py로 연결한다. 승인 ①②와 반려 시 되돌리기. 인기 영상 참고(선택). 시간이 되면 Colab에서 3번 방법 시험주제 하나를 넣으면 품질은 부족해도 영상이 끝까지 나온다
4주차 다듬기·완성최종 영상 합성, 시험 주제 3개 점검, 사용 설명서·발표 자료, 오류 수정. 다 끝나면 고도화 작업을 고려최종 영상 1편이 승인 ①②를 거쳐 다운로드되고 발표 시연이 가능하다

무료 한도와 위험

2026-10-14~16에 확인한 값이다. 무료 서비스는 한도와 조건이 예고 없이 바뀔 수 있으므로, 1주차에 각자 가입 화면과 요금표를 캡처해 팀 채널에 올린다. 확인 방식과 출처 링크는 기존 기획서(20261015)의 "확인 결과와 출처"를 참고한다.

서비스확인한 무료 한도넘으면대처
Gemini API한국은 지원 지역이고 Flash·Flash-Lite 텍스트 모델의 입력·출력이 무료다(공식 가격표). 요청 횟수 한도는 모델마다 다르고 문서에 숫자가 없다. 직접 측정(10/15): gemini-3.5-flash-lite에 1초에 1번 보냈더니 23번 성공 후 24번째(약 34초)에 429가 났고 오류 본문에 "limit: 15"(모델당 분당)가 표시됐다. 하루 한도는 태평양시 자정(한국 시간 오후 4~5시경)에 초기화된다429 오류장면 대본을 한 번에 요청해 호출 수를 줄이고, 오류가 나면 잠시 기다려 재시도한다. 무료 등급은 입력이 Google 제품 개선에 쓰일 수 있어 개인정보를 넣지 않는다
YouTube Data API프로젝트당 하루: 검색 100회, 영상 업로드 100회, 나머지 호출은 합쳐 10,000유닛(영상·채널 조회는 1회 1유닛). 태평양시 자정에 초기화. 수업에서 받은 키로 인기 영상 조회(videos.list, KR 10개)가 200 OK로 작동함을 확인했다(10/15)그날 호출이 막힌다검색 대신 조회 호출을 쓰고 결과를 파일로 저장해 재사용한다
Tavily한 달 1,000크레딧, 기본 검색 1회 1크레딧, 카드 불필요. 매월 1일 초기화다음 달까지 중단주제 1개에 검색 3~5회만 쓴다 (한 사람이 한 달에 영상 약 200편 분량)
Pexels API신규 API 키 발급이 중단된 상태다(Pexels 공식 API 안내 페이지의 안내 문구, 10/16 검색으로 확인. 재개 시점은 안내 없음). 기존 키 한도는 시간당 200회, 월 20,000회이고 화면에 Pexels 링크 표시가 필요했다(키를 못 받음)1순위에서 뺐다. 이미 키가 있는 사람만 쓰고, 나머지는 Pixabay나 AI 그림으로 간다
Pixabay API (대체)로그인하면 키를 받는다. 기본 한도는 키당 60초에 100회, 요청 결과를 24시간 저장해야 하고 대량 일괄 다운로드는 금지, 화면에 출처를 표시해야 한다. 영상 검색 주소는 /api/videos/ (공식 문서 확인, 10/16). 가입 절차와 영상 사용 약관은 직접 확인하지 못했다429 오류1주차에 키 발급과 약관을 확인한다. 같은 검색은 24시간 저장한다
Cloudflare Workers AI하루 10,000뉴런, 한국 시간 오전 9시에 초기화. FLUX.1 schnell은 1024×1024 한 장이 약 58뉴런이라 하루 약 170장. FLUX.2 klein 4B는 한 장 약 104뉴런(하루 약 96장)요청이 실패한다(요금 없음)영상 1편에 그림 6~10장만 쓰고 만든 그림은 저장해 재사용한다. 움직임만 고칠 때는 그림을 다시 만들지 않는다
edge-tts공식 한도 표기 없음. Microsoft Edge의 온라인 음성 서비스를 키 없이 쓰는 비공식 도구라 서비스 쪽 변경이 있으면 막힐 수 있고, 팀원 리서치대로 약관 확인이 필요하다. 팀 PC에서 한국어 음성 3종 × 문장 5개(mp3·srt 15건)가 모두 성공했다(10/15)음성이 안 만들어진다만든 음성 파일을 저장해 두고 1주차에 대체 음성 방법 1개를 시험한다
Google Colab 무료한도를 공개하지 않고 GPU를 보장하지 않는다. 한 번에 최대 12시간이고 오래 놀면 종료된다. 웹 화면으로 콘텐츠를 만드는 사용은 무료 등급에서 자주 종료된다접속이 안 되거나 끊긴다3번 방법은 "되면 좋은 것"으로만 두고 노트북 코드 셀로 실행한다

결론. 위 한도로는 각자 하루에 영상을 몇 편 만들어도 Tavily·Cloudflare 한도 안에 든다(Gemini는 1주차에 확인). 병목은 YouTube 검색(하루 100회), Gemini 분당 호출, edge-tts의 불안정이다. 스톡 영상 공급처는 Pexels 키 중단으로 불확실해졌으므로 기본 방법을 AI 그림 + 움직임으로 두는 것이 더 안전하다.

팀 규칙과 고도화 작업

  • 각자 자기 폴더에서 작업하고, 공용 파일 형식은 2주차 말 확정 뒤 채널에 먼저 알린 뒤에만 바꾼다
  • 서로 더블체크한다 (개발 과정). 한 사람이 만든 조각은 다른 팀원이 돌려 보고 합친다. 시험 주제 3개로 만든 영상은 만든 사람이 아닌 팀원이 출처·대본·화면의 실수를 점검한다. 이는 팀이 프로젝트를 만드는 동안의 약속이며, 앱의 승인 기능과는 별개이다
  • 코드는 GitHub Private 저장소에 올리고, 가지 → Pull Request → 팀원 1명이 "돌아가는지"만 돌려 보고 합친다. Claude Code로 만든 코드는 직접 돌려 본 뒤 올리고 자기 조각을 말로 설명할 수 있어야 한다
  • 막히면 30분 안에 화면 캡처와 함께 채널에 올린다. 주 1회 60분 모임에서 각자 돌아가는 것을 직접 보여 준다
  • API 키는 각자 PC의 .env에만 두고 저장소에 올리지 않는다. 결제 수단은 어느 서비스에도 연결하지 않는다

일정 조율. 빠듯하면 이 순서로 줄인다: 3번 방법(AI 영상) → 스톡 보완 → 인기 영상 반영 → "추천해 줘" 버튼 → 영상 미리보기 꾸미기. 어느 경우에도 주제 → 조사·대본 → 승인 → 음성·이미지·영상화 → 합성 → 승인·다운로드의 한 줄기를 먼저 끝까지 완성한다.

고도화 후보. 영상 품질 높이기와 AI 영상 확대 / 인기 영상 화면·대사 분석(제목·조회수 같은 공개 정보만 참고) / 자동 업로드(YouTube, TikTok·인스타그램은 처음엔 사람이 직접) / 내 영상·사진 올리기(Whisper), 롱폼, 로그인, 모바일 앱

완료 기준과 시작 전에 정할 것

  • ☐ 주제를 넣으면 출처 링크가 확인된 조사와 근거가 달린 장면별 대본이 화면에 나온다
  • ☐ 4명 모두 각자 만든 프로그램을 시연했고, 그 비교로 역할과 이미지 기본 방법을 정했다 (2주차)
  • ☐ 대본을 승인하면 음성·자막·장면 그림·클립이 만들어지고 영상으로 합쳐진다
  • ☐ 반려하면 고른 단계(대본·음성·이미지·영상화)부터 다시 만들어지고 대본 버전이 남는다
  • ☐ 사용자가 승인 ①②를 눌러야 다음 단계로 넘어가고, 완성 영상을 승인한 뒤 다운로드할 수 있다. 최종 영상 1편(60초 안팎)이 완성되었다
  • ☐ 개발 과정에서 팀원끼리 조각과 시험 영상을 서로 점검했다 (Pull Request 검토, 시험 주제 3개 교차 점검)
  • ☐ 쓴 돈이 0원이고 결제 수단을 연결하지 않았다
  • ☐ 4명 모두 자기 조각을 발표에서 설명할 수 있고, 사용 설명서·발표 자료가 완성되었다

시작 전에 정할 것. 시작일과 점검 시간(수요일 모임) / 각자 PC의 그래픽 카드와 8GB PC 사양(수요일 모임) / 프로그램 안의 AI를 Gemini 무료 등급으로 확정할지(1주차) / 스톡 영상 공급처: Pixabay 키 발급·약관 확인(1주차) / 팀원끼리 시험 영상을 돌려 볼 공유 방법: 공유 폴더 또는 메신저(1주차) / 음성 대체 방법(1주차) / YouTube 키가 아직 작동하는지, 같은 프로젝트의 키인지(1주차) / 이미지 방법을 누가 시험할지(1주차)

아직 확인하지 못한 것. 음성 품질을 사람이 들어 보는 평가, Colab에서 Wan 2.2가 우리 용도로 도는지, Pixabay 키 발급과 약관, Pexels 발급 중단이 언제 풀리는지. 확인 결과와 출처, 1주차 직접 시험 결과는 기존 기획서(20261015)를 참고한다.
